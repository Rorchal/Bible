# 讲道录音 RAG

把讲圣经的录音，做成一个能问答、能溯源的检索库。

## 整体思路

```
录音 ──①转录──▶ 原始文本 ──②提炼──▶ 结构化文稿 ──③切块──▶ 检索块 ──④建库──▶ RAG
                data/01_raw    data/02_refined   data/03_chunks   data/04_index
```

| 步骤 | 做什么 | 状态 |
|---|---|---|
| ① 转录 | 录音 → 文字 | ⏭️ 跳过（你已有转录文本） |
| ② 提炼 | 清洗 ASR 噪声、加标点、修专名、按论述结构分段 | ✅ 已实现 |
| ③ 切块 | 把段落切成适合向量检索的块，带上下文前缀 | ⬜ 待做 |
| ④ 建库 | 向量化 + 混合检索 + 带引用的问答 | ⬜ 待做 |

---

## ⚠️ 一个容易走错的地方：第二步是"整理"，不是"摘要"

很多人做到第二步会让模型"总结每一段"，然后拿总结去建 RAG。**这是错的。**

RAG 检索出来的内容要直接喂给模型回答问题，讲员举的例子、打的比方、
讲的故事、具体的生活应用——正是最有价值的部分。一摘要，这些全没了，
最后问答出来的东西空洞、千篇一律，跟直接问模型没区别。

所以第二步的规则是：**正文一字不少地保留，只去噪声、加结构。**
摘要和标题另存进 metadata，将来第三步拿它们当检索的上下文前缀用。

脚本会自己算**保留率**（整理后字数 ÷ 原文字数）。正常在 85%–100%。
低于 70% 会告警，说明模型偷偷摘要了，要重跑。

## 第二步：提炼

**1. 把转录文本放进 `data/01_raw/`**，一段录音一个文件。
支持 `.txt` / `.srt` / `.vtt`，详见 [`data/01_raw/README.md`](data/01_raw/README.md)。

> 如果你的转录带时间轴（`.srt`/`.vtt`），**优先用带时间轴的**。
> 时间戳会被带进每一段，将来检索命中时能直接定位到录音的第几分钟。

**2. 先空跑看看**

```bash
python -m pipeline.refine --dry-run
```

**3. 正式跑**

```bash
python -m pipeline.refine
```

每个文件产出两份：

- `data/02_refined/<名字>.json` —— 给第三步用的结构化数据
- `data/02_refined/<名字>.md` —— **给你人工校对的**

**请一定打开 `.md` 扫一遍。** 重点看圣经专名有没有改错、经文引用对不对。
第二步的错误会一路带到最后的问答里，在这里挡住成本最低。

**校对时发现反复出现的同一个错字，就往热词表里加一条**（见下），
下次以及后续所有录音都不会再错。

### 热词表：修正 ASR 的固定错字

ASR 对专有名词和不常用词会稳定地认错同一批字。这类错误交给模型不保险，
用一张表确定性地改掉更可靠。表在 [`data/hotwords.txt`](data/hotwords.txt)，
随时可以往里加：

有两种规则：

```
# ① 正确词 = 错写      确定性替换，直接改掉
敬虔 = 尽钱, 近钱
灵界 = 零界

# 错写本身是正常词时，用 ! 列出不该动的例外
义人 = 艺人 ! 手艺人, 工艺人, 演艺人员, 文艺人

# ② 正确词 ? 易混词    不改文本，只提示模型按上下文判断
义人 ? 一人 ! 因一人的悖逆, 因一人犯罪, 因一人的顺从
恶人 ? 二人 ! 二人成为一体, 二人同心, 夫妻二人
```

**用 `=` 还是 `?`，看这个错写本身是不是常用词。**

`尽钱`、`零界` 不是正常中文词，怎么替换都不会误伤 → 用 `=`。

`一人`、`二人` 是极常用的词，而且正好在核心经文里：
罗马书 5:19「因**一人**的悖逆……因**一人**的顺从」、
创世记 2:24「**二人**成为一体」、阿摩司书 3:3「**二人**若不同心」。
盲替换会得到「因义人的悖逆」「恶人成为一体」，例外列表也列不完
→ 只能用 `?`，把两个候选都告诉模型，让它逐处看上下文决定。

`艺人` 介于两者之间：单独出现时基本就是 `义人`，但 `手艺人` 里含它
→ 用 `=` 加例外列表护住固定搭配。

**`!` 例外列表**在两种规则下作用不同：
`=` 规则的例外会先换成占位符护住，替换完再还原；
`?` 规则的例外作为反例写进提示词，告诉模型这些说法本身是对的。
两种都会校验——例外词里如果根本不含对应的错写（打错字了），加载时直接报错。

替换做两遍：送模型**之前**先改（让模型读到通顺的文本），模型输出**之后**
再兜一遍（模型偶尔会把正确词又写回错的）。同时正确词会作为术语表进提示词。

每次运行会报告每个词命中多少次：

```
热词表：5 条
  确定性替换：敬虔、灵界、义人
  交给模型判断：义人、恶人
  2024-03-提摩太前书  9840 字  有时间轴  分 1 批  热词命中：敬虔×7
```

用这个数字审计你加的规则——命中数异常高，多半是规则写宽了。
（只有 `=` 规则会计数；`?` 规则不碰文本，改没改要看 `.md`。）

> ⚠️ `=` 规则是直接的子串替换，中文又没有词边界。加新词前想两件事：
> 1. 这个错写会不会是某个正常词的一部分？（→ 加例外列表，或改用 `?`）
> 2. 这个错写本身会不会就是讲员真想说的词？（→ 改用 `?`）
>
> 拿不准就用 `?`。它最差不过是模型判断错一处，而 `=` 判断错会错满全篇。

命中记录也会写进 JSON 的 `hotword_hits` 字段，事后可查。

### 常用参数


## 代码结构

```
pipeline/
├── common.py    输入解析（txt/srt/vtt）、中文断句、分窗
├── hotwords.py  热词表的加载与替换
├── prompts.py   第二步的提示词和 JSON schema
└── refine.py    第二步主流程 + CLI

data/
└── hotwords.txt  ← 你随时往里加错字规则
```

长文会自动分批（默认每批 12000 字），分批时各段先各自整理，
最后再单独归纳一次总标题和主旨。系统提示词开了 prompt caching，
连跑多个文件时重复部分不重复计费。

## 成本大致估算

用 Claude Opus 5，输入 $5/百万 token、输出 $25/百万 token。
中文约 1 字 ≈ 1 token，一篇一小时讲道约 1 万字：

- 输入 ~1 万 token ≈ $0.05
- 输出 ~1 万 token ≈ $0.25

**一篇约 $0.3，十篇约 $3。** 想省钱可以把 `pipeline/refine.py` 里的
`MODEL` 换成 `claude-sonnet-5`（约便宜 60%），整理这类任务质量差别不大。

## 下一步

- 以第二步的 segment 为单位，超长的再切，短的合并
